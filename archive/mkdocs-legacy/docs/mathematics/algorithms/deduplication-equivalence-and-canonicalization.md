# Deduplication, equivalence, and canonicalization

## Purpose

CALM performs several distinct deduplication operations. They are not a single algorithm, because the objects being compared live in different spaces and require different equivalence relations. This specification records the mathematical contracts used to identify equivalent structures, surface supercells, interface candidates, and interface prototypes without confusing scientific identity with representation identity.

The main implemented families are:

1. supercell-search deduplication by surface point-group action;
2. optional metric-signature grouping of reduced two-dimensional cells;
3. prototype/contact-layer canonicalization by internal translation and integer hashing;
4. geometric prototype grouping by metric and contact-motif signatures;
5. atom-level duplicate detection/removal in Cartesian structure validation utilities.

## Ontology mapping

| Layer | Input object or representation | Equivalence relation | Output |
| --- | --- | --- | --- |
| Surface supercell search | HNF supercell representatives for a slab surface | same sublattice under surface point-group action | one representative per canonical key |
| Reduced-metric grouping | reduced Gram matrices | same quantized in-plane metric | grouped or optionally collapsed candidates |
| Interface prototype signatures | integer contact-layer records and HNF matrices | same canonical HNF and same translated contact record set | deterministic prototype signature/hash |
| Interface prototype grouping | built prototype search results | same quantized metric and contact distance multiset | stable groups for inspection/ranking |
| Atom validation | ASE-like atom positions | atoms closer than tolerance under MIC | duplicate pairs or a copy with selected duplicates removed |

These operations are representation morphisms when they select or encode an equivalent representative. They become scientific admissibility filters only when a caller explicitly discards all but one representative from a scientific search space.

## Mathematical formulation

### Surface point-group deduplication

Let \(L \subset \mathbb{R}^2\) be a primitive in-plane lattice basis and let \(H \in \mathbb{Z}^{2\times 2}\) be a right-column HNF with positive determinant \(k\). The supercell sublattice is represented by

\[
N = H U,
\]

where \(U\) is the unimodular change of basis produced by two-dimensional reduction. Let \(G\) be the finite point group of the slab surface, represented as integer operations on the primitive surface basis. Two supercell embeddings are equivalent if there exists \(P \in G\) such that their integer sublattice representatives differ by the induced action of \(P\), followed by canonical HNF reduction. CALM represents the orbit by a canonical point-group key.

The implemented search keeps the lowest-condition representative for each key at fixed index \(k\). This preserves one representative of each point-group orbit while avoiding duplicate orientations generated by the HNF enumeration.

### Metric-signature grouping

For a reduced in-plane supercell basis \(S\), define the symmetric Gram matrix

\[
G_S = S^T S.
\]

A metric signature is formed by quantizing the independent components of \(G_S\):

\[
q(G_S) = \left( \operatorname{round}(sG_{11}),\operatorname{round}(sG_{12}),\operatorname{round}(sG_{22}) \right),
\]

where \(s\) is the configured scale. Equal metric signatures imply numerically indistinguishable metric data at the selected precision, but not necessarily the same embedded sublattice. For that reason, metric collapsing is optional and disabled by default in the supercell index construction.

### Prototype contact-layer canonicalization

An interface contact layer is represented by integer records whose first columns contain integer in-plane coordinates and species/atomic labels. CALM first converts the associated supercell matrix to canonical two-dimensional HNF. It then chooses a canonical record set by minimizing, in lexicographic byte order, over a finite set of internal translations:

\[
R^* = \min_{t \in T} \operatorname{lexsort}(R - t),
\]

where \(t\) shifts the integer in-plane coordinates. The canonicalized integer array is serialized as contiguous `int64` bytes and hashed with SHA-256. The resulting contact hash, together with the determinant and canonical HNF tuple, forms the prototype signature.

The exhaustive translation search is intentionally conservative and capped for tractability. Therefore this signature is a deterministic grouping aid, not a proof of complete crystallographic isomorphism for all possible supercells.

### Contact-motif distance grouping

For prototype search results, CALM also defines a lightweight contact-motif signature from the sorted multiset of in-plane pairwise distances among interface atoms:

\[
D = \operatorname{sort}\{\|x_i - x_j\|_2 : 1 \le i < j \le n\}.
\]

Distances are quantized by a tolerance \(\tau\), producing an integer tuple. This signature is translation and atom-order invariant, and it is useful for grouping similar registries. It is not a complete structural invariant because it omits species-pair labeling, periodic image choices beyond the implemented coordinates, and higher-order geometry.

### Atom-level duplicate detection

For validation utilities, two atoms are duplicates if their minimum-image distance is below a user-specified tolerance:

\[
d_{\mathrm{MIC}}(i,j) < \varepsilon.
\]

The removal operation preserves one atom from each duplicate pair according to the configured `first` or `last` strategy. This is a structure-cleaning utility rather than an interface-prototype equivalence relation.

## Algorithmic contracts

### Supercell search deduplication

Inputs:

- primitive in-plane basis;
- maximum HNF index;
- surface point-group operations;
- condition-number threshold;
- deduplication flags.

Workflow:

1. Enumerate all canonical two-dimensional HNFs of index \(k\).
2. Build and reduce each supercell basis.
3. Reject cells that fail conditioning or reduction constraints.
4. Compute the canonical point-group key for the embedded integer supercell representative.
5. At each fixed \(k\), keep the representative with minimal condition number for each key.
6. Optionally group or collapse by quantized metric signature.

Outputs:

- a dictionary from index \(k\) to kept reduced supercell representatives;
- optional audit counters: total HNFs, generated cells, kept cells, symmetry removals, and metric removals.

Complexity:

- HNF enumeration scales as \(\sum_{k \le k_{\max}} d(k)\), where \(d(k)\) is the divisor count for index \(k\).
- point-group deduplication adds a factor proportional to the number of surface point-group operations.
- metric grouping is linear in the number of kept reduced cells.

### Prototype-signature construction

Inputs:

- a two-dimensional integer supercell matrix;
- non-empty integer contact-layer records.

Workflow:

1. Convert the supercell matrix to canonical HNF.
2. Compute the positive determinant.
3. Enumerate capped internal translations over the determinant-sized subgroup approximation.
4. Lexicographically sort translated record arrays.
5. Choose the smallest byte representation.
6. Hash contiguous `int64` bytes with SHA-256.
7. Return determinant, compact HNF tuple, and contact hash.

Outputs:

- a stable prototype signature.

Complexity:

- approximately \(O(c^2 N \log N)\), where \(N\) is the number of records and \(c = \min(\det H, 64)\) in the current implementation.

### Geometric prototype grouping

Inputs:

- prototype search results;
- metric scale;
- motif tolerance.

Workflow:

1. Compute a quantized reduced-metric signature from each result Gram matrix.
2. Compute a quantized sorted in-plane pair-distance signature from interface atom positions.
3. Group first by metric signature, then by motif signature.
4. Sort each group by match score.

Outputs:

- nested dictionaries from metric signature to motif signature to sorted result list.

Complexity:

- metric signature construction is \(O(1)\) per result;
- motif signature construction is \(O(n^2 \log n)\) for \(n\) atoms in a prototype result.

## Correctness properties

The deduplication routines are expected to satisfy the following properties within their declared tolerance model:

- **Determinism:** equal inputs produce equal keys, signatures, and grouping order.
- **Permutation invariance:** prototype integer records are lexicographically sorted before hashing, making the hash insensitive to record order after canonicalization.
- **Translation invariance:** prototype contact signatures minimize over internal translations in the implemented finite domain.
- **Point-group orbit representative selection:** supercell search keeps one low-condition representative per canonical point-group key.
- **Tolerance locality:** metric and motif signatures only identify equivalence at the explicitly selected quantization scale or tolerance.
- **No unintended public identity change:** candidate display identifiers, provenance UIDs, prototype hashes, and persistence projections remain distinct identity layers.

## Limitations and non-goals

- Metric signatures are not complete lattice-embedding invariants; equal Gram matrices can correspond to distinct sublattice embeddings.
- Pairwise-distance motif signatures are useful grouping heuristics, not complete crystallographic graph isomorphism checks.
- Prototype translation canonicalization uses a capped exhaustive search and should not be interpreted as an exhaustive proof for arbitrary large determinant supercells.
- Atom duplicate removal is tolerance-based and strategy-dependent; it is not a scientific equivalence proof.
- Deduplication can intentionally reduce search multiplicity, but correctness claims depend on which equivalence relation the caller chooses.

## Implementation mapping

## Implementation notes (migrated from legacy supercell enumeration guide)

### Point-group orbit key notes

Practical details for constructing orbit keys:

- Compute the canonical orbit key from the total integer transform `N_tot` using the left action of normalized surface point-group operators: `key_pg = canonical_hnf_key_under_pg(N_tot, PG_ops)`.
- The canonical key is the lexicographically minimal HNF tuple from the orbit; implementors should avoid floating-point operations when generating keys.
- Normalize and freeze `PG_ops` once per enumeration to avoid repeated validation overhead in hot loops.

### Best-by-orbit selection notes

Selection guidance:

- Keep one representative per `(k, key_pg)` orbit, choosing the supercell with minimal raw-basis condition number as the primary selection criterion.
- Use lexicographic HNF tie-breaking when conditioning numbers are equal within tolerance to preserve determinism.

### Metric-dedup caution

Metric-based deduplication notes and warning:

- Collapsing by reduced metric can discard distinct embedded sublattices because equal Gram matrices do not guarantee identical lattice embeddings. Keep metric-dedup OFF by default and clearly warn callers when enabling it.

### Edge cases

Common edge cases implementors should plan for:

- Empty point group (no symmetry): treat `PG_ops = [np.eye(2)]` (no deduplication).
- Highly symmetric lattices: expect stronger orbit compression (C6 → ~6× reduction); ensure caching mitigates repeated orbit checks.
- Ill-conditioned primitives: if the primitive in-plane basis is near-singular, many supercells will fail the conditioning gate; prefer preprocessing or looser `cond_max` in those cases.

## Verification mapping

Current verification should cover at least:

- deterministic key/hash construction for fixed integer records;
- invariance under record order and implemented translation operations;
- distinction between point-group deduplication and metric grouping;
- preservation of candidate/prototype/public projection identity boundaries;
- tolerance sensitivity for metric and atom duplicate operations;
- dependency-light collection when optional ASE/spglib backends are unavailable.

Future verification should add explicit counterexamples showing why metric equivalence is not sufficient to collapse embedded sublattices unless that behavior is deliberately requested.
