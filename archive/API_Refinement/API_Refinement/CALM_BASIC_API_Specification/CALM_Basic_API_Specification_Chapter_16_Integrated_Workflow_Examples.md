# CALM Basic API Specification

# Chapter 16 — Integrated Workflow Examples

## Purpose

The previous chapters specified the public objects, collections,
workflow semantics, and collection contracts of the CALM Basic API.

This chapter demonstrates how those components compose into complete
scientific workflows.

The examples are intentionally concise.

Their purpose is not to teach users how to perform calculations—that is
the role of the handbook—but to demonstrate that the Basic API provides
a coherent, consistent interface across the entire scientific workflow.

---

# 1. Complete Interface Workflow

The complete workflow follows the scientific object lifecycle defined in
Chapter 3.

```text
Project
    ↓
Materials
    ↓
Surfaces
    ↓
Matches
    ↓
Interfaces
    ↓
Relaxations
    ↓
Analyses
    ↓
Datasets
```

Every workflow stage consumes persisted scientific objects generated by
earlier stages.

No workflow stage reconstructs previously generated objects.

---

# 2. Project Initialization

```python
project = Project.create(
    "lif_li2o",
)

project.configure(
    mlip="mace-medium",
)
```

The Project establishes the scientific investigation and default
computational environment.

---

# 3. Materials

```python
project.materials.import(
    "LiF.vasp",
)

project.materials.import(
    "Li2O.vasp",
)

lif = project.materials.get("LiF")

li2o = project.materials.get("Li2O")
```

Scientific objects are immediately persisted within the Project.

---

# 4. Surface Generation

```python
project.surfaces.generate(
    material=lif,
    millers=[
        (1,0,0),
        (1,1,0),
    ],
)

project.surfaces.generate(
    material=li2o,
    millers=[
        (1,0,0),
    ],
)

film = project.surfaces.get("LiF (100)")

substrate = project.surfaces.get("Li2O (100)")
```

Previously generated Materials are retrieved rather than reconstructed.

---

# 5. Interface Matching

```python
search = project.matches.search(
    film=film,
    substrate=substrate,
)

matches = search.results()

matches.plot_pareto()
```

The search produces persisted Match objects.

---

# 6. Interface Construction

```python
match = matches.best()

interface = project.interfaces.build(
    match=match,
)

project.interfaces.partition_strain(
    interface,
)

project.interfaces.optimize_registry(
    interface,
)
```

The Interface is constructed from a persisted Match.

---

# 7. Structural Relaxation

```python
relaxation = project.relaxations.run(
    interface=interface,
)
```

The Relaxation consumes a persisted Interface.

---

# 8. Scientific Analysis

```python
energy = project.analyses.run(
    interface_energy,
    relaxation,
)

strain = project.analyses.run(
    strain_analysis,
    relaxation,
)
```

Scientific analyses consume previously generated scientific objects.

---

# 9. Dataset Assembly

```python
dataset = project.datasets.create(
    analyses=[
        energy,
        strain,
    ],
)

project.datasets.export(
    dataset,
    "lif_li2o_dataset.zip",
)
```

The Dataset packages the scientific results without modifying any of the
underlying objects.

# 10. Workflow Principles

These examples demonstrate the defining characteristics of the Basic
API.

## Persisted Object Lifecycle

Every workflow stage retrieves persisted scientific objects rather than
reconstructing them.

---

## Collection Ownership

Every scientific operation belongs to exactly one collection.

Examples include:

```python
project.materials.import(...)

project.surfaces.generate(...)

project.matches.search(...)

project.interfaces.build(...)

project.relaxations.run(...)

project.analyses.run(...)
```

The Project coordinates the workflow while collections own the
operations.

---

## Consistent Vocabulary

The same public vocabulary appears throughout the workflow.

Examples include:

- `get()`
- `list()`
- `find()`
- `export()`

Scientific operations use names that reflect their scientific meaning.

Examples include:

- `generate()`
- `search()`
- `build()`
- `run()`

---

## Provenance Preservation

Every scientific object records its parent objects.

The complete provenance graph remains available throughout the
investigation.

---

# 11. Scientific Questions

The complete workflow enables users to answer questions such as:

- Which materials should I study?
- Which surfaces should be generated?
- Which interfaces are crystallographically compatible?
- Which interface should be constructed?
- What is the relaxed interface structure?
- Which interface is most stable?
- Can this investigation be reproduced?

---

# 12. Design Rationale

The integrated workflow demonstrates that the Basic API is organized
around scientific investigations rather than individual computational
operations.

Every stage:

- consumes persisted scientific objects,
- produces new persisted scientific objects,
- preserves provenance,
- follows the same collection-oriented interface.

This consistency is the defining characteristic of the Basic API.
